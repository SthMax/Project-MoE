
下面给你把 **实验 1.1（多数据集观察 expert activation 分布）** 做到“工程可落地”的 **逐步操作手册**。默认你们的目标模型是 **Qwen3-Next-80B-A3B（E=512, top-k≈10+shared）**，并且你希望尽量走 **vLLM** 路线（最后能变成系统）。

---

## 实验 1.1 的定义（先把“你要统计什么”固定）

### 你要输出的核心数据结构

对每个 **MoE layer** $l=1..L$，每个 **expert** $e=1..E(=512)$，在每个数据集/域 ddd 上统计：

- `cnt_topk[d, l, e]`：被分到 expert e 的 token 数（top-k 内，含 shared 你可单独统计）
    
- `cnt_top1[d, l, e]`：top-1 expert 的 token 数
    
- （可选但很有用）`sum_w[d, l, e]`：gate weight（归一化后）的累加，用于看“虽然选了，但权重很小”的情况
    

最终你会画：

- layer×expert 的负载热力图（utilization）
    
- 不均衡指标（Gini / CV / max-to-mean / entropy）
    
- 不同数据域之间的分布差异（JSD / cosine）
    

> **注意**：这个实验不需要保存“每个 token 的路由”，只要在线聚合即可，否则数据量会爆。

## Step 0：硬件/模型选择的“安全配置”

你们是 **4×A100 40GB**，建议先用 **短上下文**做 1.1，避免 KV cache 干扰、也更稳：

- `tensor_parallel_size = 4`
    
- `max_model_len = 4096 或 8192`（足够做统计）
    
- 权重：优先 FP8/量化版本（你们只做路由统计，不追求极致精度）
    
- 并发：先用 `max_num_seqs = 8~16` 做稳定跑通（后面再加）

因为 **vLLM 默认不会把 router/topk 暴露出来**，你要做实验 1.1 就必须插桩。  
同时 vLLM 的 MoE 路由是抽象出来的（例如 `FusedMoERouter`、`select_experts`），非常适合插桩。

**做法**

1. 从源码安装 vLLM（不要 pip wheel），保证你能改：
    
    - `git clone vllm ...`
        
    - `pip install -e .`
        
2. 固定版本号（commit hash），写进实验日志（你后面写 paper 需要可复现）

## Step 2：准备数据集（确保“跨域对比”干净）

### 2.1 选择 4 个域（建议）

- General text：wikitext / c4 子集
    
- Code：mbpp / humaneval prompts
    
- Math/Reasoning：gsm8k（题目部分）/ math 子集
    
- Multilingual：flores 子集 / 自己的中英混合语料
    

### 2.2 统一采样规则（非常重要）

每个域做同样的预处理：

- 抽样 `N = 2k~10k` 条（先从 2k 跑通）
    
- 每条截断到固定 token 长度（比如 `T=512` 或 `T=1024`）
    
- 同一个 tokenizer（模型自带 tokenizer）
    
- 记录每条的 token 数、平均长度（写 paper 要交代）
    

**产物**

- 你最终生成一个 JSONL / Parquet：
    
    - `{"domain": "...", "text": "...", "id": "...", "n_tokens": ...}`

## Step 3：决定“执行方式”（prefill-only 最合适）

你做 activation 分布，最理想是只跑 **prefill（teacher forcing）**，不做生成。

但 vLLM 的高层 API `generate()` 通常会至少 decode 一步。工程上我建议这样做：

- 设 `max_tokens=1`，让 decode 的那 1 个 token 对统计影响几乎为 0（比如 prompt 512 token，decode 1 token，只占 0.2%）
    
- temperature=0，减少随机性
    
- 你不需要 logprobs 来做 1.1，所以 `prompt_logprobs` 可以关掉（后续 1.2/1.3 需要 ppl 再开）
    
    - vLLM 确实支持 `prompt_logprobs`（后面算 perplexity 会用到）。

## Step 4：实现“在线聚合”的 RoutingStatsCollector（核心工程）

### 4.1 插桩点选哪里？

目标是拿到：

- `topk_indices`（shape 类似 `[num_tokens, k]`）
    
- （可选）`topk_weights` 或 gate weights
    
- 以及“这是第几层 MoE”（layer_id）
    

最稳的插桩点：**router 的 `select_experts`**  
因为那里一定会产生 top-k indices。

### 4.2 如何拿到 layer_id？

你需要让每个 MoE layer 的 router 知道自己是第几层。两种方法：

**方法 A（推荐，侵入小）**  
在模型构建完之后，遍历所有 MoE block，把 `router.layer_id = idx` 填进去。

**方法 B（侵入大但更干净）**  
改 router 构造函数，把 layer_id 当参数传进去。

> 你先用 A，跑通最快。

### 4.3 在线聚合怎么写（避免性能崩）

你要避免每 token 写日志。正确姿势是“每个 forward 做一次 bincount”：

- 对 top-k：
    
    - `hist = bincount(topk_indices.flatten(), minlength=E)` → 得到 512 维直方图
        
    - 加到 `cnt_topk[layer] += hist`
        
- 对 top-1：
    
    - `hist1 = bincount(topk_indices[:,0], minlength=E)`
        
    - 加到 `cnt_top1[layer] += hist1`
        
- 对权重（可选）：
    
    - `sum_w[layer, expert] += sum(weights[token, expert])`
        
    - 实现上可以用 scatter_add
        

**关键性能建议**

- `bincount` 在 GPU 上做，然后只把 512 维向量拷到 CPU 累加（很便宜）
    
- 只在 `rank==0` 统计（TP 下通常每 rank 会看到相同路由；先这样做最安全）
    
- 每处理完一个 domain（或每 M=1000 个 batch）flush 一次到磁盘
    

### 4.4 输出文件格式（建议）

每个 domain 输出一个文件（方便后处理）：

- `routing_stats_<domain>.npz`
    
    - `cnt_topk`: `[L, E]` int64
        
    - `cnt_top1`: `[L, E]` int64
        
    - `sum_w`: `[L, E]` float64（可选）
        
    - `meta`: JSON（model、tp、max_len、N、T、vllm_commit、时间戳）

## Step 5：运行主循环（按 domain 跑）

对每个 domain：

1. 读入该域的 prompts 列表（建议一次性加载到内存）
    
2. 用 vLLM 创建 `LLM(...)`（TP=4，max_model_len 固定）
    
3. 调用 `generate(prompts, SamplingParams(max_tokens=1, temperature=0))`
    
4. 你的 collector 会自动累计并在结束时 flush
    
5. 记录 vLLM 的吞吐（可选，1.1 不强制）

## Step 6：后处理与指标计算（写 paper 的“图表产线”）

你从每个 domain 的 `[L,E]` 统计出：

### 6.1 utilization（负载分布）

$$
u_{l,e} = \frac{\text{cnt\_topk}[l,e]}{\sum_{e'} \text{cnt\_topk}[l,e']}
$$​

### 6.2 不均衡指标（每层一条曲线）

- `max/mean`: $\max_e u_{l,e} / \mathrm{mean}_e u_{l,e}$
    
- `CV`: std/mean
    
- `entropy`:  $-\sum_e u_{l,e}\log u_{l,e}$
    
- `Gini`（建议写出来，会很有说服力）
    

### 6.3 域间差异（同一层）

对每层 l，计算不同 domain 的 $u_{l,\cdot}$：

- cosine similarity / Jensen–Shannon divergence
    

### 6.4 推荐你最终要出的 3 张“最值钱”的图

1. **Layer×Expert heatmap**（每个 domain 一张）
    
2. **不均衡度 vs layer**（每个 domain 一条线）
    
3. **域间差异 vs layer**（证明 routing 对 domain 有响应）
    

---

## Step 7：Sanity Check（避免你插桩错了还不知道）

强烈建议做 3 个检查：

1. **计数守恒**
    

- 对每层：`sum_e cnt_topk[l,e]` 应该约等于 `total_tokens_processed * k_eff`
    
- 其中 `k_eff` = top-k（如果 shared 单独算就分开）
    

2. **不同 batch size / 并发下，分布是否稳定**
    

- 同一 domain，换 `max_num_seqs`（8→16→32），看 utilization rank 是否大体一致
    
    - 如果变化巨大，说明你统计被系统态影响（这个也可能是你后续论文点，但 1.1 先要搞清楚原因）
        

3. **对照 Transformers（小样本即可）**
    

- 抽 50 条样本，用 HF Transformers 打开 `output_router_logits` 跑一次，看看 top-k 直方图是否量级一致（只做“方向性验证”即可）。
