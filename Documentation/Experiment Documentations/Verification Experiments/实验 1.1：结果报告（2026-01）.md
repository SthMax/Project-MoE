## 0. 摘要（给未来的你快速回忆）

本次实验用 vLLM 在线聚合路由统计，验证了：

1) **域间差异显著**：跨域 pairwise JS divergence 在多个层上稳定存在，且“代码/执行类任务（HumanEval）”与其他域差异最大。

2) **decode 更“尖峰 + 更分化”**：在所有 4 个 decode-focused runs 中，decode 的跨域 JSD 平均值均高于 total/prefill；同时 decode 的 `top1_max_share` 更高、`top1_entropy_norm` 更低（尤其在 HumanEval / GSM8K）。

3) **top-k 相比 top-1 更稳定**：同一 run 内，`js_topk_mean` 的平均值系统性低于 `js_top1_mean`，说明“候选集合”比“最强专家”更稳健。

4) **模型间差异存在但结论一致**：
   - Qwen3-Next-80B-A3B（FP8, E=512, k=10, shared always-on）总体跨域 JSD 较高。
   - Qwen3-30B-A3B（BF16/auto, E=128, k=8, no shared）总体跨域 JSD 较低，但 top-1 更尖峰（更高 `top1_max_share`）。

这些结果支持了 1.1 的核心目的：给后续的 fluid / queue-aware routing 提供“到达率分布随 domain 变化”的实证输入，并提示后续实验应优先关注 **decode 场景**（因为它更贴近 serving bottleneck，且路由更极端）。

## 1. 实验目标与可验证假设（从 1.1 文档与聊天假设抽象）

**目标（E1.1）**：测量 MoE 路由的“到达过程/arrival process”在不同语义域上的分布形态：
- 每层每 expert 的到达率/负载分布（top1/topk/shared）。
- 域间分布差异（JSD）。
- 分布的尖峰程度/不均衡（entropy, gini, max-share 等）。

**本报告验证的假设**（可用本次数据直接支持/反驳）：

- H1（Domain sensitivity）：不同 domain 的路由分布显著不同（JSD 远离 0），且差异集中在某些层。
- H2（Decode amplifies）：decode 的分布更“尖峰/不均衡”，并放大域间差异（decode 的 JSD/max-share 更高）。
- H3（Top-k robustness）：top-k 分布比 top-1 更稳定（`js_topk_mean` < `js_top1_mean`）。

## 2. 方法与产物（工程口径）

### 2.1 统计口径（在线聚合）

- 每个 MoE layer $l$、每个 expert $e$：
  - `cnt_top1[l,e]`：top-1 routed expert 命中次数
  - `cnt_topk[l,e]`：top-k membership 命中次数
  - `cnt_shared[l]`：shared expert 命中次数（如果模型有 shared，且实现为 always-on，则期望 `shared_frac≈1`）
- phase split（同一个 `.npz` 内同时包含 total/prefill/decode）：
  - `*_prefill` / `*_decode` 版本计数与 token 数。

### 2.2 Phase split 的可信度说明（prefill vs decode）

本次使用 **token-level mask** 在 vLLM v1 路径上区分 prefill/decode，并显式避免 warmup/dummy forward 污染；worker shutdown 触发显式 flush，降低只靠 `atexit` 导致的丢文件风险。

验证手段：每个 domain 的 [meta.json](../../../Code/Verification/E1.1/outputs/runs/20260114_qwen30ba3b_qa_decode/gsm8k/meta.json) 里记录了 `sanity_ok_topk(_prefill/_decode)` 等守恒检查结果（本次抽查均为 true）。

### 2.3 每个 domain 的主要产物

以任意 domain 为例：
- `routing_stats_merged.npz`：聚合后的计数（total/prefill/decode 全在一个文件里）
- `routing_summary*.json` / `routing_summary_layers*.csv`：全局与逐层统计（entropy/max-share/gini 等）
- `routing_analysis.json`：逐层 top experts + 异常层 flag（如 entropy_norm 过低 / max_share 过高）
- `plots/`：
  - `heatmap_top50_experts_top1(_prefill/_decode).png`
  - `heatmap_top50_experts_topk(_prefill/_decode).png`
  - `entropy_by_layer(_prefill/_decode).png`
  - `max_share_by_layer(_prefill/_decode).png`
  - `shared_frac_by_layer(_prefill/_decode).png`

run-level 产物：
- `run_analysis.json`：所有 domain pair 的跨层 JS divergence 统计（total/prefill/decode）

## 4. 结果：跨域差异（run-level `run_analysis.json`）

### 4.1 总体结论：decode 的跨域 JSD 平均值更高

下表取自每个 run 的 `run_analysis.json`，对所有 domain pair 的 `js_top{1,k}_mean` 做平均：

| Run | 域数量 | `js_top1_mean`(total) | `js_top1_mean`(decode) | `js_topk_mean`(total) | `js_topk_mean`(decode) |
|---|---:|---:|---:|---:|---:|
| A: qwen3next_decode | 5 | 0.400 | 0.484 | 0.318 | 0.389 |
| B: qwen30ba3b_decode | 5 | 0.350 | 0.426 | 0.254 | 0.315 |
| C: qwen3next_qa_decode | 6 | 0.367 | 0.408 | 0.284 | 0.325 |
| D: qwen30ba3b_qa_decode | 6 | 0.309 | 0.345 | 0.224 | 0.261 |

**观察**：
- 4/4 runs：decode 平均 JSD > total。
- 4/4 runs：top1 JSD > topk JSD。
- 同一 domain set 下：Qwen3-Next 的平均 JSD > Qwen3-30B-A3B（两组 runs 都成立）。

## 5. 结果：分布尖峰程度（per-domain `routing_summary*.json`）

### 5.1 decode 更尖峰：`top1_max_share` 增大，`top1_entropy_norm` 降低

以下取每个 run 中 **top1_max_share 最大的几个 domain**（越大越说明 top1 过于集中），并对比 total vs decode：

- Run A（qwen3next_decode）：[20260113_qwen3next_decode](../../../Code/Verification/E1.1/outputs/runs/20260113_qwen3next_decode/)
  - HumanEval：total 0.185 → decode 0.241；entropy_norm：0.644 → 0.522
  - GSM8K：total 0.145 → decode 0.181；entropy_norm：0.675 → 0.542

- Run B（qwen30ba3b_decode）：[20260114_qwen30ba3b_decode](../../../Code/Verification/E1.1/outputs/runs/20260114_qwen30ba3b_decode/)
  - HumanEval：total 0.270 → decode 0.331；entropy_norm：0.633 → 0.510
  - GSM8K：total 0.166 → decode 0.236；entropy_norm：0.692 → 0.557

- Run C（qwen3next_qa_decode）：[20260113_qwen3next_qa_decode](../../../Code/Verification/E1.1/outputs/runs/20260113_qwen3next_qa_decode/)
  - HumanEval：total 0.174 → decode 0.176；entropy_norm：0.658 → 0.609
  - GSM8K：total 0.126 → decode 0.130；entropy_norm：0.693 → 0.636

- Run D（qwen30ba3b_qa_decode）：[20260114_qwen30ba3b_qa_decode](../../../Code/Verification/E1.1/outputs/runs/20260114_qwen30ba3b_qa_decode/)
  - HumanEval：total 0.261 → decode 0.276；entropy_norm：0.642 → 0.578
  - GSM8K：total 0.156 → decode 0.178；entropy_norm：0.708 → 0.657

**结论**：decode 的尖峰化在“CulturaX/General/Code/Math”混合域更明显；在 QA 域中仍存在但幅度相对小（可能因为 QA 的 prompt 更模板化，token 语义分布更均匀，或者因为 token 数更大导致统计更平滑）。

### 5.2 模型结构差异（shared expert）会改变解释口径

- Qwen3-Next-80B-A3B：`shared_frac≈1`（shared always-on），因此系统层面的带宽/激活压力不能只看 routed experts，还应结合 shared 计算模式。
  - 例：[routing_summary.json](../../../Code/Verification/E1.1/outputs/runs/20260113_qwen3next_qa_decode/gsm8k/routing_summary.json)

- Qwen3-30B-A3B：`shared_frac=0`（无 shared），top1/topk 统计更直接对应“专家负载”。
  - 例：[routing_summary.json](../../../Code/Verification/E1.1/outputs/runs/20260114_qwen30ba3b_qa_decode/gsm8k/routing_summary.json)

## 7. 对后续（fluid / queue-aware routing）的直接启示

1) **arrival 向量必须按 domain 建模**：跨域 JSD 不是噪声；把 arrival 当成单一分布会错得很离谱。

2) **decode 是系统瓶颈侧的关键**：decode 更尖峰、更分化，和实际 serving 的 MoE 带宽/通信瓶颈吻合（见 [Chat/260112 Gemini-3Pro Proposal for CS.md](../../../Chat/260112%20Gemini-3Pro%20Proposal%20for%20CS.md) 关于 decode memory-bound 与拥塞/队列的讨论）。

3) **优先做“HumanEval vs 其他域”的对照实验**：它在 4 个 runs 里一致地制造最大跨域差异，适合作为“构造热点/验证 queue-aware 策略收益”的首选 workload。
